## 任务：让 nmf 实验能在 3090 服务器上跑（配置 conda 环境 + 跑实验）

用户要在 3090 服务器上跑同一套 NMF 实验，问环境与实验指令。审计后发现**代码在 CUDA 上根本跑不通**，
以及三个 shell 脚本都硬编码了本机 python 路径 —— 都已在本次修掉。

### ★ 修掉 5 处「GPU 必定崩溃 / 静默失效」的问题

| # | 位置 | 问题 | 修法 |
| --- | --- | --- | --- |
| 1 | `nmf_layers.make_shift` | `offset` 用 `torch.full/torch.zeros` 建在 **CPU**，`W - offset` 在 CUDA 上直接报设备不一致（默认 `shift=min` 必崩） | 加 `device=W.device, dtype=W.dtype` |
| 2 | `nmf_layers.init_nndsvd` | A/S/B 建在 CPU，与 CUDA 的 `W_target` 运算时崩 | 全部按 `W.device/dtype` 创建；SVD 异常兜底路径也传 device |
| 3 | `nmf_layers.init_random_nonnegative` | 无 device 参数 | 新增 `device/dtype` 参数：随机数在 CPU 生成后搬运（保证同 seed 跨设备初值一致） |
| 4 | `esm_common.apply_mlm_mask` | `torch.rand(shape, generator=<CPU gen>)` 没有 device → CUDA 上 `eligible & rand` 崩；且 CPU generator 配 CUDA 会报 "Expected a 'cuda' device type for generator" | 改成 CPU 生成再 `.to(tokens.device)`；顺带保证 CPU/GPU 遮挡位置完全一致 |
| 5 | `factorize.py` | `device = resolve_device(...)` 算了但**从未使用**，模型没 `.to(device)` → `--device cuda` 被静默忽略（一直在 CPU 上算） | `model = model.eval().to(device)`；`--device` 帮助文本说明 HALS 未必适合 GPU |

另外 `factorize_matrix` 里加了兜底：init 之后把 A/S/B 统一 `.to(W_target.device/dtype)`。
`ThreeFactorNMFLinear.__init__` / `set_offset` 里的无 device 创建是**安全的**（参数在 CPU 创建，
由调用方 `.to(device)`；`set_offset` 里紧接 `copy_(value.to(...))`），不动。

### 脚本可移植化：新增 `nmf/_env.sh`（三个 run_*.sh 共同 source）

- 解析解释器：`PY` > 当前 PATH 里的 `python`/`python3`，都没有就报错并提示 `conda activate` / `PY=...`；
- 设备：`DEVICE`（默认 auto）/ `FACTORIZE_DEVICE`（默认跟随 DEVICE），并提供 `nmf_check_device`
  在 `DEVICE=cuda` 但 `torch.cuda.is_available()` 为 False 时**明确警告并回退 CPU**（不静默变慢）；
- `TMPDIR` 默认 `<仓库>/.tmp`（已加 .gitignore），不再硬编码 `/home/zzj/tmp`；不再强制 `HOME`；
- `nmf_env_report` 打印 python/torch/cuda/GPU 名称与显存。
- `run_all.sh` / `run_full_experiment.sh` / `run_matrix.sh` 全部改为 source 它，并给每个 python 调用
  传 `--device`（`run_matrix.sh` 之前硬编码 `--device cpu`，等于在 3090 上白跑）。
